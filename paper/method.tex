\section{Method}
\label{sec:method}

\subsection{Overview}
Given a question $q$, supplied tables $\mathcal{T}$, and an associated passage
pool $\mathcal{D}$, the framework constructs a bounded knowledge graph $G_q$
specifically for $q$ at query time. Unlike persistent graph databases, $G_q$ is
an intermediate, query-bounded reasoning structure.

Previous grounded graph-RAG architectures suffer from a fundamental tension:
filtering the evidence graph to only the top-$N$ ranked paths reduces prompt
noise, but can discard peripheral corroborating facts or fail when several
candidates tie on path score. Conversely, passing an uncurated graph overwhelms
the language model with unstructured triples.

To resolve this trade-off, we propose the \textbf{Online Unified Evidence Graph
(OUEG)} framework alongside the classic \textbf{Grounded Path-Text} view. The
complete pipeline proceeds as follows:
\begin{align*}
q &\rightarrow \text{two-stage context retrieval} \\
  &\rightarrow \text{schema-preserving online KG construction} \\
  &\rightarrow \begin{cases}
    \text{grounded path enumeration \& scoring} \\
    \text{subgraph prompt compression}
  \end{cases} \\
  &\rightarrow \text{ambiguity assessment} \rightarrow \text{grounded answer}.
\end{align*}
Candidate paths serve as prioritized \emph{non-filtering reading guides} over
the complete unified subgraph rather than destructive filters. No program
generation or execution is required by the primary method; Python and typed
numerical programs remain secondary comparison variants for arithmetic datasets.

\subsection{Query-Driven Two-Stage Retrieval}
\label{sec:method-retrieval}
Benchmark settings supply an oracle table and an associated pool of linked
passages. Retrieval operates within this supplied context.

\paragraph{Stage 1: Coarse retrieval.}
BM25 indexes table rows and text passages with respect to question $q$. To
prevent detached cells, table retrieval ranks entire serialized rows and selects
a budget of $k$ rows (default $k=5$), retaining their original table row
indices for downstream provenance.

\paragraph{Stage 2: Bridge-entity and hyperlink expansion.}
Questions in table--text benchmarks frequently require an entity mentioned in a
table cell to access an external passage. A deterministic query anchor inspects
$q$ for:
\begin{enumerate}
    \item \emph{Ordinal constraints}: A regex recognizer matches words
    (\emph{first}, \emph{second}, \dots) or numeric ordinals (\emph{1st},
    \emph{2nd}, \dots) and resolves the matching row index.
    \item \emph{Exact schema constraints}: Specific column header mentions and
    numerical filters.
    \item \emph{Hyperlink-directed passage expansion}: For every cell in the
    retrieved top-$k$ rows, dataset adapters harvest Wikipedia hyperlinks
    (\texttt{linked\_passage} URLs). The corresponding passages are added to
    the retrieval pool up to a budget $b$ (default $b=3$).
\end{enumerate}
Passage retrieval combines direct BM25 passage matches with hyperlink expansions
and bridge-entity queries, deduplicating passages by source identifier.

\subsection{Schema-Preserving Online KG Construction}
\label{sec:method-kg}
For each question, the system instantiates a directed multigraph
$G_q=(V_q, E_q)$. An edge $e \in E_q$ is defined as
\[
e = (h, r, t, \pi),
\]
where $h$ and $t$ denote head and tail node labels, $r$ is a normalized relation,
and $\pi$ stores provenance metadata including source type (\texttt{table} or
\texttt{text}), source identifier, row index, column name, and header path.

\paragraph{Deterministic table edges and record nodes.}
Flattened tables lose header hierarchies and intra-row bindings. We address this
with two structural representations:
\begin{enumerate}
    \item \emph{Qualified headers}: Hierarchical column headers are qualified
    into normalized relation keys (e.g., \texttt{2002 / Dividend} becomes
    \texttt{2002\_dividend}).
    \item \emph{Record nodes}: Direct subject--value edges
    $(u_i, \operatorname{norm}(H_j), v_{ij})$ permit entity lookups but do not
    guarantee that values from the same row remain bound. For each row $i$, we
    introduce a local record node $\rho_i = \texttt{table:}T\texttt{:row:}i$:
    \[
    u_i \xrightarrow{\mathrm{has\_record}} \rho_i, \qquad
    \rho_i \xrightarrow{\operatorname{norm}(H_j)} v_{ij}.
    \]
    This structural star topology ensures that attributes such as year, venue,
    and score belonging to row $i$ cannot be conflated with those of another row
    sharing the same entity subject.
    \item \emph{Multi-value cell splitting}: When a table cell contains multiple
    comma-separated values, the adapter splits them into individual
    \texttt{derived\_from\_cell\_split} edges so that target entities are not
    masked within compound strings.
\end{enumerate}
In parallel, an audit trace records the explicit
$\text{Table} \rightarrow \text{Row} \rightarrow \text{Cell} \rightarrow \text{Column}$
topology without altering the semantic reasoning graph.

\paragraph{Text edges and rule-based extraction.}
For retrieved passages, semantic triples connect entities to their attributes
and linked passage nodes ($u \xrightarrow{\mathrm{linked\_passage}} \text{passage\_id}$).
To avoid the latency, API costs, and hallucinations of unstructured LLM triple
extraction, the primary extractor employs deterministic rule-based patterns
(\texttt{rule\_text\_triples}) alongside lexical entity-linking. Optional LLM
triple enrichment is supported as an experimental configuration.

\paragraph{Entity normalization and resolution.}
Nodes undergo four-stage resolution: (1) lexical normalization (Unicode,
casing, whitespace, punctuation); (2) configured domain aliases; (3) structural
name cleanup (removing club/corporation prefixes/suffixes); and (4) conservative
string similarity (threshold $\ge 0.93$ restricted to identical entity roles).
All resolution merges are recorded in an auditable resolution log.

\subsection{Grounded Path Generation and Scoring}
\label{sec:method-paths}
The reasoning edge set $E_q^*$ unites semantic edges, record edges, and
hyperlink edges. Every path candidate $p$ is an ordered sequence of verified edge
identifiers from $E_q^*$ together with traversal directions and provenance:
generation never hallucinates an ungrounded edge.

\paragraph{Candidate search.}
Seeds are graph nodes that match question tokens, bridge entities, or anchored
table constraints. Bounded depth-first search enumerates connected simple paths
up to 5 hops ($|E_p| \le 5$). Additionally, the planner synthesizes
\emph{row bundles}: subgraphs connecting $u_i \rightarrow \rho_i$ with the most
question-relevant outgoing cell edges of row $i$, keeping multi-attribute
constraints co-located.

\paragraph{Multi-factor path scoring.}
Paths are scored deterministically via:
\[
S(p) = G + Q_e + Q_r + Q_c + C + M + R + B + A - 0.35 \max(|E_p|-1, 0),
\]
where $G=1$ is edge-groundedness validity; $Q_e, Q_r \in [0, 2]$ denote question
overlap with nodes and relations; $Q_c \in [0, 2]$ is question token coverage;
$C=2$ rewards matching an anchored table constraint; $M=1.5$ awards cross-modal
evidence combining table and text; $A=1.0$ credits identical-fact corroboration;
$R=1.0$ rewards row consistency; and $B=1.0$ requires explicit
\texttt{has\_record} binding.

\subsection{Online Unified Evidence Graph (OUEG) and Prompt Compression}
\label{sec:method-oueg}
In the classic Path-Text baseline, only the top-$N$ ranked paths are serialized,
discarding the remainder of $G_q$. In the \textbf{Online Unified Evidence Graph
(OUEG)}, the language model receives the entire unified subgraph
$G_q^{\text{unified}} = (V_q^*, E_q^*)$ alongside the raw text contexts, with
the generated candidate paths provided as \emph{non-filtering suggested reading
guides}.

\paragraph{Prompt compression and context deduplication.}
Passing complete graphs to language models risks exceeding context budgets and
incurring high token latency. OUEG incorporates a compact serializer
(\texttt{CompactOUEGPromptBuilder}):
\begin{enumerate}
    \item \emph{Edge deduplication}: Multiple edges sharing identical endpoints
    and relations are merged, aggregating their provenance contexts into a
    compact identifier list.
    \item \emph{Shared context dictionary}: Passage text snippets are indexed by
    source ID in a shared text dictionary rather than duplicated across individual
    edges.
    \item \emph{Node role annotations}: Nodes in the serialized prompt are
    annotated with their candidate path memberships, step indices, and row order
    indices.
\end{enumerate}

\subsection{Ambiguity Assessment and Score-Collision Handling}
\label{sec:method-ambiguity}
A pervasive challenge in structured table QA is \emph{structural ambiguity}:
multiple candidate rows often satisfy the coarse question constraints with
identical path scores. For example, when asked for ``the club whose city is
between Kgale and Oodi Hills'', several rows may match the country/league
condition, creating a score tie.

OUEG actively detects these collisions during candidate generation:
\begin{enumerate}
    \item \emph{Tie classification}: If two or more distinct candidate paths
    achieve identical maximal scores, the status is flagged as
    \texttt{SCORE\_COLLISION\_TIE}; if multiple rows match without a score tie,
    it is labelled \texttt{MULTIPLE\_\allowbreak STRUCTURAL\_\allowbreak CANDIDATES}.
    \item \emph{Lexical tiebreak}: When a collision occurs, OUEG computes the
    lexical overlap between candidate entity labels and bridge-entity passage
    mentions. If a unique lexical winner exists, it is highlighted as a
    tiebreak signal in the prompt.
    \item \emph{Prompting instructions}: The answer synthesizer is alerted of
    potential ambiguity, prompting it to verify subtle textual nuances in the
    deduplicated contexts rather than arbitrarily selecting the first row.
\end{enumerate}

\subsection{Answer Generation, Fallback, and Audit Trace}
\label{sec:method-answer}
The final answer model receives the compressed unified subgraph (or top-ranked
paths), suggested path reading guides, ordering hints (e.g., explicit ordinal
ranks), ambiguity diagnostics, and the question. The model extracts a concise
denotation span.

\paragraph{Reverse grounding and empty fallback.}
If the path search yields no valid candidates or the graph is disconnected,
the pipeline activates \emph{reverse grounding}: the answer model performs
evidence-conditioned direct synthesis over the retrieved rows and passages,
and the extracted entity is reverse-mapped onto $G_q$ to recover provenance. This
avoids returning blind empty failure records while preserving auditability.

\paragraph{Audit record.}
Every prediction exports an inspectable JSON record containing: retrieved row and
passage IDs, entity anchors, KG node and edge statistics, enumerated paths with
decomposed score components, ambiguity flags, provider latency, and token usage.
