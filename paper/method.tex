\subsection{Stage 1: Multi-Source Evidence Ingestion}
\label{sec:method-retrieval}
Benchmark settings supply an oracle table and an associated pool of linked passages. Retrieval operates dynamically within this context.

\paragraph{Coarse row retrieval and query anchoring.}
A lexical retriever indexes table rows with respect to question $q$. To capture structural constraints beyond unigram word matching, a deterministic query anchor inspects $q$ for: (1)~\emph{ordinal constraints}, matching word or digit ordinals (e.g., ``second'', ``last'') to table row indices; and (2)~\emph{exact schema constraints}, identifying column header mentions and numerical filters. Table retrieval ranks candidate serialized rows under these constraints and selects a budget of $k$ rows (default $k=5$). In our running example (Fig.~\ref{fig:pipeline}, Stage~1), the temporal constraint ``formed in 1989'' successfully anchors Row~0 (\texttt{Tor. Eagles}) from table \texttt{AFL\_Ontario\_0}.

\paragraph{Hyperlink passage expansion.}
Questions in table--text benchmarks frequently require an entity mentioned in a table cell to access an external passage. Rather than retrieving entire document corpora indiscriminately, the passage expander directly harvests Wikipedia hyperlinks (\texttt{linked\_passage} URLs) embedded in candidate cells of the top-$k$ retrieved rows up to a budget of $b$ passages (default $b=3$). In Fig.~\ref{fig:pipeline}, the bridge cell \texttt{Toronto} in Row~0 links to \texttt{Doc:Toronto}. These hyperlink expansions are united with direct lexical passage matches and deduplicated by source document identifier.

\subsection{Stage 2: Schema-Preserving Multigraph Construction}
\label{sec:method-kg}
Using the retrieved rows and passages, the system dynamically instantiates the bounded multigraph $G_q=(V_q, E_q)$ partitioned as in Eq.~\eqref{eq:graph-partition}. Each directed edge $e = (h, r, t, \pi) \in E_q$ connects head and tail nodes $h, t \in V_q$ with a normalized relation predicate $r$ and provenance metadata $\pi$ (source type, row index, column name, and header path).

\paragraph{Deterministic table edges and record centroids.}
Flattened tables lose header hierarchies and intra-row bindings. Direct subject--value edges $(u_i, \operatorname{norm}(H_j), v_{ij})$ permit entity lookups but fail to guarantee that values from the same row remain bound. For each row $i$, we introduce a local centroid record node $\rho_i = \texttt{table:}T\texttt{:row:}i \in V_{\text{rec}}$ with star-topology bindings (Fig.~\ref{fig:pipeline}, Stage~2):
\begin{equation}
\label{eq:star-topology}
E_{\text{rec}} = \{ (u_i, \texttt{has\_record}, \rho_i) \}, \qquad
E_{\text{attr}} = \{ (\rho_i, \operatorname{norm}(H_j), v_{ij}) \}.
\end{equation}
In Fig.~\ref{fig:pipeline}, centroid $\rho_0$ binds row attributes (\texttt{city}, \texttt{formed}, \texttt{club}), ensuring they cannot be conflated with attributes of another row. When a table cell contains multiple comma-separated values, the adapter splits them into individual derived edges. In parallel, an audit trace records the explicit $\text{Table} \rightarrow \text{Row} \rightarrow \text{Cell} \rightarrow \text{Column}$ topology without altering the semantic reasoning graph.

\paragraph{Hyperlink bridging and rule-based text extraction.}
Hyperlink edges $E_{\text{link}}$ connect table cell entities to external passage nodes (e.g., $\text{Toronto} \xrightarrow{\ell} \text{Doc:Toronto}$). For retrieved passages, semantic triples $E_{\text{text}}$ connect entities to textual attributes (e.g., $\text{Doc:Toronto} \xrightarrow{\texttt{orig\_name}} \text{York}$). To avoid the latency, API costs, and instability of unconstrained LLM triple extraction, the extractor employs deterministic rule-based patterns (\texttt{rule\_text\_triples}) alongside lexical entity-linking.

\paragraph{Entity normalization and resolution.}
Nodes undergo four-stage resolution: (1) lexical normalization (Unicode, casing, whitespace, punctuation); (2) configured domain aliases; (3) structural name cleanup (removing club/corporation prefixes/suffixes); and (4) conservative string similarity (threshold $\ge 0.93$ restricted to identical entity roles), recorded in an auditable resolution log.

\subsection{Stage 3: Dual-Track Reasoning Engine}
\label{sec:method-engine}
\label{sec:method-oueg}
OUEG-RAG avoids the false dichotomy between hard path filtering (which discards vital peripheral context) and uncurated triple passing (which overflows context budgets). Stage~3 coordinates three complementary tracks:

\paragraph{Track 3a: Compact subgraph compression.}
Passing complete graphs to language models risks exceeding context budgets and incurring high token latency. OUEG incorporates a compact serializer (\texttt{CompactOUEGPromptBuilder}): (1)~\emph{Edge deduplication}: multiple edges sharing identical endpoints and relations are merged, aggregating provenance IDs; (2)~\emph{Shared context dictionary}: passage text snippets are indexed by source ID in a shared text dictionary rather than duplicated; and (3)~\emph{Compact JSON-style encoding}: candidate rows are serialized into dense attribute maps (e.g., \texttt{\{"rec":$\rho_0$, "yr":"1989", "city":"Toronto"\}} in Fig.~\ref{fig:pipeline}, Stage~3).

\paragraph{Track 3b: Grounded path traversal and scoring.}
\label{sec:method-paths}
Every path candidate $p$ is an ordered sequence of verified edges from $E_q^*$ connecting query seeds to candidate answers. Depth-first search enumerates connected simple paths up to 5 hops ($|E_p| \le 5$) and row bundles. Paths are scored deterministically via:
\begin{equation}
\label{eq:path-score}
S(p) = G + Q_e + Q_r + Q_c + C + M + R + B + A - \lambda_{\text{len}} \max(|E_p|-1, 0),
\end{equation}
where $G=1$ is edge validity; $Q_e, Q_r \in [0, 2]$ denote question overlap with nodes and relations; $Q_c \in [0, 2]$ is token coverage; $C=2$ rewards matching an anchored table constraint; $M=1.5$ awards cross-modal table-text fusion; $A=1.0$ credits identical-fact corroboration; $R=1.0$ rewards row consistency; $B=1.0$ requires \texttt{has\_record} binding; and $\lambda_{\text{len}}=0.35$ penalizes redundant hops. Weights were fixed from an initial 50-sample pilot. In Fig.~\ref{fig:pipeline}, the grounded path $p_1$ ($\text{Eagles} \rightarrow \rho_0 \rightarrow \text{Toronto} \rightarrow \text{York}$) reaches maximal score $S(p_1) = 7.85$.

\paragraph{Track 3c: Structural ambiguity and collision tiebreaking.}
\label{sec:method-ambiguity}
Let $\mathcal{P}_q$ be valid paths, and $S^* = \max_{p \in \mathcal{P}_q} S(p)$. The candidate collision set $\mathcal{C}_q$ comprises distinct target entities reaching this maximal score:
\begin{equation}
\label{eq:collision-set}
\mathcal{C}_q = \{ \operatorname{tail}(p) \mid p \in \mathcal{P}_q, \, S(p) = S^* \}.
\end{equation}
When $|\mathcal{C}_q| > 1$, multiple rows tie on coarse structural scores (e.g., $p_1$ vs.\ $p_2$ in Fig.~\ref{fig:pipeline}, both achieving $S^*=7.85$). To resolve collisions deterministically without hallucination, OUEG formulates a bridge lexical tiebreak score $\tau(c)$ over bridge passage tokens $\mathcal{D}_q^{\text{bridge}}$:
\begin{equation}
\label{eq:tiebreak-score}
\tau(c) = \sum_{w \in \operatorname{Tokens}(c) \cap \operatorname{Tokens}(\mathcal{D}_q^{\text{bridge}})} \operatorname{IDF}(w), \qquad
c^* = \arg\max_{c \in \mathcal{C}_q} \tau(c).
\end{equation}
In our example, candidate $\rho_0$ yields $\tau=1.84 > 0.42$, breaking the symmetry and establishing $c^* = \rho_0$ as the prioritized grounding signal.

\subsection{Stage 4: Grounded Generation and Provenance Audit}
\label{sec:method-answer}
Stage~4 couples the compressed evidence multigraph with non-filtering guidance to generate the final verified span and export an auditable provenance trace.

\paragraph{Prompt assembly and LLM decoding.}
The prompt payload unifies: (1)~\emph{Context}: the complete compressed multigraph $G_q^{\text{unified}}$ and deduplicated passage dictionary; (2)~\emph{Guide}: the top scored path $p_1$ provided strictly as a prioritized non-filtering reading guide; (3)~\emph{Anchor}: the tiebreak winner $c^*$; and (4)~\emph{Question}. The frozen backbone LLM ($T=0$) executes single-turn greedy decoding, correctly extracting the grounded span \texttt{"York"}.

\paragraph{Audit trace and reverse fallback.}
Every prediction exports an inspectable JSON record detailing: retrieved row indices (\texttt{AFL\_Ontario\_0:row:0}), bridge URLs (\texttt{/wiki/Toronto}), traversed edge path, and target text excerpt (\texttt{town of York (1793)}). If graph search disconnects, \emph{reverse grounding} directly synthesizes over retrieved evidence and maps the extracted span back onto $G_q$, avoiding blind empty failures.
